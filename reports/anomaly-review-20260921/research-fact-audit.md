# Anomaly research: factual, logical and editorial review

Reviewed 2026-09-21. Author: Andrey Pautov. Review scope: the complete expanded **Malicious Activity as a Statistical Signal** article, including its original Sections 1–11, not only the new incident cards.

## Verdict

The research has a useful organizing idea: examine behavior against explicit context, then corroborate deviations with independent evidence. The expanded case cards make the distinction between reported behavior and proposed detection clearer. **The complete article is not yet suitable as a validated implementation reference.** Its older sections contain factual errors, unsupported generalizations, citation mismatches, and non-runnable or logically incomplete queries. Adding case studies does not repair these older claims.

This is a review with explicit unresolved findings, not a claim that every sentence is correct. No accuracy percentage, detector precision, recall, or universal threshold is assigned. The work did not execute KQL/SPL in Sentinel or Splunk, replay incidents, examine victims' private telemetry, or independently reproduce vendor detections. Static tests demonstrate selected logical counterexamples only.

### Scope boundaries

- **Research audit:** reviewed the article's definitions, taxonomy, campaign accounts, telemetry descriptions, code examples, implementation advice, conclusion and references. Primary documents were consulted for the concrete corrections below. Unsupported claims remain unresolved, not silently accepted.
- **Ecosystem relevance scan:** 943 content records were retrieved/read by the corpus scanner; 146 candidate pages received contextual tag review. This is not a factual audit of all 943 articles/guides. Non-candidates were scanned, not individually certified irrelevant.
- **New incident register:** now covers 14 feature families plus the original article's overlooked multi-event-correlation section: 15 topics, 30 mappings, 17 distinct case/campaign records and 17 primary documents. Repeated mappings are not independent incidents.
- **What changed in this pass:** the taxonomy omission, topic metadata, crosslinks and discovery integration. The legacy technical prose and eleven code blocks were retained for review; the findings below are **open remediation work unless explicitly marked fixed or verified**. They must not be reported as repaired.

| 3. ATT&CK mapping | Treat ATT&CK as a behavior/tactic taxonomy, not a required linear lifecycle. Several tactic and observability claims need qualification. |

| 7. Evasion | Baseline poisoning, low-and-slow behavior and missing telemetry are credible failure modes. Avoid treating proposed evasions as measured outcomes for every campaign. |

| 9. Implementation | Role-scoped comparison and exercises are useful. Universal priority rules and baseline-free confidence claims contradict that advice. |
| 10. Conclusion | Overstates what the evidence demonstrates and contradicts the caveats in the new incident cards. |
| 11. References | Primary sources are preferable, but reachable URLs are not sufficient: title, date and supported claim must match. Some legacy references fail that requirement. |

## Editorial quality

Preserve the author's technical voice, but make the evidence boundaries consistent throughout. Specific improvements needed:

1. Replace the conclusion's detector-success claims with the narrower conclusions actually supported by the case register.
2. Remove universal words such as “never,” “any,” “only,” and “near-zero” where no measured or logically necessary boundary exists.
3. Distinguish an attack, its observable feature, a proposed analytic, a working implementation, and a validated detection result.
4. Normalize broken Markdown spacing, escaped blockquote markers, pseudo-table lists and heading levels. Retain stable anchors and all 44 images; image preservation is not independent validation of diagram content.
5. Use source-specific citations next to claims, not one reference after a paragraph that merges incidents. Deduplicate case evidence across anomaly families.
6. Name a telemetry contract for every query: product/version, table, event provider/channel, required fields, audit prerequisites, entity keys, lookback, collection completeness and allowable enrichment.
7. Separate original article, documented case additions and later technical corrections in the change history. Do not silently call retained broken examples “corrected queries.”

## Required evidence before claiming production readiness

Restore and compile each real query in its target engine. Test true positives, benign administration, unrelated users in the same window, reversed event order, parser aliases, ingestion delay, computer-account abuse, missing fields, zero-variance baselines and cold starts. Freeze thresholds before evaluating a held-out corpus. Report alert precision, incident recall, false alerts per entity-day, collection coverage and confidence intervals with their denominators. Purple-team success is a coverage observation for that test, not a global false-positive estimate.

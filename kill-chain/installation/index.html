Understanding Installation

Installation is the establishment of an adversary-controlled component in the compromised environment. An implant, backdoor, malicious extension, or web shell can give the operator a foothold from which to continue. The relevant evidence is the component and the changes that made it available for use.

Typical activities

  • Place or load a malicious executable, script, web shell, or other component.
  • Change a service, scheduled task, startup entry, or application configuration to support continued access.
  • Prepare the foothold to survive expected interruptions when the operation requires persistence.

Example: After an application compromise, a new web shell appears in a server directory. File-change records, application requests, and process events can help establish when it was placed and whether it was used.

Installation and persistence overlap, but are not identical. A newly deployed component may be temporary, and persistence can rely on identity or configuration changes rather than a conventional installed program. Memory-only activity may leave little durable file evidence.

Defender’s question: What new component or configuration established the foothold, and which evidence distinguishes it from an authorized change?

Relevant ATT&CK techniques 7 examples

These curated Enterprise ATT&CK techniques and sub-techniques illustrate behavior relevant to Installation. They are not an exhaustive checklist or an official one-to-one mapping. ATT&CK tactics describe goals; the IDs below identify techniques. A technique may appear in more than one stage when the context justifies it.

  • T1547.001Registry Run Keys / Startup Folder

    Sub-technique of T1547 — Boot or Logon Autostart Execution

    A startup entry can arrange repeated execution of an implanted component; correlate it with the referenced file and process.

  • T1543.003Windows Service

    Sub-technique of T1543 — Create or Modify System Process

    A Windows service can establish execution and continued access for a newly deployed component.

  • T1543.002Systemd Service

    Sub-technique of T1543 — Create or Modify System Process

    A systemd service can establish execution of a component on a Linux host.

  • T1053.005Scheduled Task

    Sub-technique of T1053 — Scheduled Task/Job

    A scheduled task can repeatedly launch a deployed payload; authorized administration is an important comparison.

  • T1505.003Web Shell

    Sub-technique of T1505 — Server Software Component

    A web shell places an operator-accessible component in a compromised server environment.

  • T1546.003Windows Management Instrumentation Event Subscription

    Sub-technique of T1546 — Event Triggered Execution

    An event subscription can establish a trigger for later execution without a conventional standalone installer.

  • T1055Process Injection

    Technique

    Injection can place code into another process as part of establishing a memory-resident foothold; it does not inherently imply persistence.

Verified against MITRE’s official STIX data, Enterprise ATT&CK v20.0, on 2026-10-31. Revoked and deprecated entries are excluded. Mapping notes and pinned source provenance (JSON).

What to look for

Examine file, process, service, task, and configuration changes. Persistence can support installation, but the two are not synonyms.

Use the model with care

The classic seven stages of Lockheed Martin’s Cyber Kill Chain are an organizing model, not a mandatory linear sequence. Stages can repeat, overlap, be skipped, or remain unobserved. Fileless, insider, identity, cloud, and AI attacks may not fit every stage. A reading association is not proof that an observed attack completed that stage.

MITRE ATT&CK describes adversary behaviors and tactical goals at a different level of detail. Its tactics are not interchangeable with these stages. The external technique links below are learning associations, not an official one-to-one mapping.

Start with CTI Kill Chain: An Analyst Guide With Real-World Evidence for case evidence and analytic limits, or the original framework reference (PDF).

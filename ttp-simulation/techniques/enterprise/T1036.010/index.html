Complete technique description

Adversaries may match or approximate the names of legitimate accounts to make newly created ones appear benign. This will typically occur during Create Account, although accounts may also be renamed at a later date. This may also coincide with Account Access Removal if the actor first deletes an account before re-creating one with the same name.[Huntress MOVEit 2023]

Often, adversaries will attempt to masquerade as service accounts, such as those associated with legitimate software, data backups, or container cluster management.[Elastic CUBA Ransomware 2022][Aquasec Kubernetes Attack 2023] They may also give accounts generic, trustworthy names, such as “admin”, “help”, or “root.”[Invictus IR Cloud Ransomware 2024] Sometimes adversaries may model account names off of those already existing in the system, as a follow-on behavior to Account Discovery.

Note that this is distinct from Impersonation, which describes impersonating specific trusted individuals or organizations, rather than user or service account names.

User Account Creation · source-mapped

DC0014 collection page — Enable Audit User Account Management and collect actor, account ID, account type and outcome from the system creating the account.

Providers and collection configuration

  • Windows Security auditing: Policy-dependent account, object, task and logon records on the host that performs the operation.
  • Active Directory domain controllers: Directory changes and authentication records; collect from the relevant controllers, not only endpoints.
  • Use a lab-only GPO under Computer Configuration → Windows Settings → Security Settings → Advanced Audit Policy Configuration. Enable the specific subcategory named below.
  • For object-level auditing, configure a narrow system access control list (SACL) on the test object in addition to policy. Do not audit an entire production directory by default.
  • Forward Security events from the responsible host or controller; retain subject and target identities, object identifiers, result and original XML. Confirm effective policy with auditpol /get /category:*.

Required normalized fields: actor, account_id, account_type, action.

DC0013 collection page — Export an authorized directory/account inventory with stable IDs, roles, enabled state and collection time; compare snapshots without exposing credentials.

Providers and collection configuration

  • osquery: Scheduled host-state queries; supported tables and privileges vary by OS. Select a table that actually exposes the required object.

DET0383 Detection Strategy for Masquerading via Account Name Similarity

MITRE detection strategy

AN1077 Analytic 1077

Detects adversary behavior where a newly created or renamed user account closely resembles existing service or administrator accounts to blend in and avoid detection. Common patterns include prefix/suffix modifications, homoglyphs, or use of names like 'admin1', 'adm1n', or 'backup_help'.

Platforms: Windows.

  • User Account Creation — WinEventLog:Security; channel EventCode=4720.
  • User Account Metadata — windows:osquery; channel User enumeration with creation/last modified timestamps.

AN1078 Analytic 1078

Detects creation or renaming of accounts with names that closely match known service, root, or admin accounts. Behavior often follows account discovery or deletion, attempting to blend into system activity logs using trusted name conventions.

Platforms: Linux.

  • User Account Creation — auditd:SYSCALL; channel adduser.
  • User Account Modification — auditd:SYSCALL; channel usermod, or account rename system calls.
  • User Account Metadata — linux:osquery; channel Listing of /etc/passwd and /etc/shadow metadata.

AN1079 Analytic 1079

Detects adversary creation of cloud or IdP accounts whose names resemble existing privileged or service accounts. May indicate preparation for privilege escalation or defense evasion.

Platforms: Identity Provider.

  • User Account Creation — azure:audit; channel Add user.
  • User Account Modification — azure:audit; channel Rename user.
  • User Account Metadata — saas:okta; channel User lifecycle events.

AN1080 Analytic 1080

Monitors for the creation of accounts inside containers using names that resemble legitimate orchestrator or backup identities to mask adversary persistence.

Platforms: Containers.

  • User Account Creation — docker:daemon; channel ExecCreate + usermod or useradd.

Anomaly engineering worksheet

Start from the exact analytic above. The collection-specific lenses below are analyst recommendations; they do not assert that an arbitrary statistical deviation detects this technique.

  • Windows and directory audit: Per principal, host and object: unusual access/request rates, new principal-object relationships, and changes outside approved administration windows. Control for service accounts and scheduled directory maintenance.
  • Host state and inventory: Compare authorized state snapshots: first-seen drivers/services/modules, unexpected configuration drift and integrity changes. Record collection cadence; absence in a sample is not evidence of deletion.
  1. Define an entity/peer group and feature; exclude the evaluation period from baseline training.
  2. Use representative normal and maintenance activity. Do not invent a production threshold from a synthetic example.
  3. Evaluate held-out behavior-positive and benign cases; measure false positives, misses and telemetry loss separately.
  4. Keep abnormality separate from maliciousness. Correlate with the behavior-specific source evidence.

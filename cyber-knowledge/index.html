Cross-domain learning and operational pathways

Cybersecurity work crosses team boundaries. These routes show which guide produces the evidence, decision, or control consumed by the next one.

Intelligence to detection

Requirement → context → tested analytic

CTI defines the question, OSINT collects attributable public evidence, and the Blue Team guide turns supported behavior into telemetry, hunting, and validation.

Exposure to remediation

Candidate surface → validated weakness → durable fix

OSINT identifies candidate external assets, Vulnerability Research establishes root cause and affected versions, and Application Security verifies the remediation and regression controls.

Adversary to evidence

Authorized simulation → detection → investigation

Red Team defines an authorized behavior and proof, Blue Team validates visibility, and DFIR with Malware Analysis preserves and explains the resulting evidence.

Architecture to assurance

Cloud design → secure delivery → governed evidence

Cloud Security assigns shared responsibilities, Secure Code integrates product and pipeline controls, and GRC connects objectives, risk, control ownership, testing, and evidence.

Start with the work you need to do

These routes connect selected chapters across multiple guides. They are practical starting points, not mandatory curricula.

I am new to cybersecurity

Build shared vocabulary, understand defensive operations, and finish with evidence and governance fundamentals.

  1. CTI: Module 1 — Foundations: What CTI Is
  2. Blue Team: Module 1 — Defensive mission, operating model, and SOC service
  3. GRC: Governance, organizational context, and accountable authority

I need to investigate an incident

Move from triage and evidence preservation into endpoint analysis and source-backed intelligence pivots.

  1. DFIR: Incident declaration, triage, scope, and hypotheses
  2. DFIR: Endpoint live response and volatile acquisition
  3. CTI: Module 4 — Collection Sources

I need to build or validate a detection

Translate behavioral intelligence into telemetry requirements, detection logic, controlled testing, and reviewable evidence.

  1. CTI: Module 8 — Operationalizing CTI (CTI → Detection)
  2. Blue Team: Module 4 — Detection engineering and detection as code
  3. Red Team: Module 8 — Threat-informed adversary emulation and purple teaming

I need to assess a vulnerability

Establish authorization and scope, reproduce safely, evaluate exploitability, and prepare remediation evidence.

  1. Vulnerability R&D: Research governance, authorization, and safety
  2. Vulnerability R&D: Exploitability validation and laboratory exploit engineering
  3. Secure Code: Vulnerability handling, remediation, disclosure, and learning

I need to conduct authorised adversary simulation

Define rules of engagement, select evidence-backed behaviors, execute controlled validation, and report defensibly.

  1. Red Team: Module 1 — Mission, authorization, and methodology
  2. Red Team: Module 8 — Threat-informed adversary emulation and purple teaming
  3. Blue Team: Module 9 — Identity defense and ITDR

I need to design a security programme

Connect governance and scenario-based risk to control ownership, evidence, metrics, resilience, and review.

  1. GRC: Governance, organizational context, and accountable authority
  2. GRC: Scenario-based cyber risk assessment and treatment
  3. GRC: Metrics, KRIs, reporting, and maturity without vanity scores

I need to research an actor or campaign

Set intelligence requirements, collect public evidence, assess sources, and produce behavior-led analytical outputs.

  1. CTI: Module 2 — The Intelligence Cycle Intelligence Types
  2. OSINT: Automation, APIs, entity graphs, normalization, and data engineering
  3. CTI: Module 6 — The Threat Actor Landscape

I need to review cloud security

Start with responsibility and identity boundaries, then assess posture, telemetry, response, and assurance evidence.

  1. Cloud Security: Shared responsibility, governance, and service ownership
  2. Cloud Security: Human, workload, pipeline, and emergency identity
  3. Cloud Security: Cloud logging, detection engineering, ATT CK, and response automation

I need to secure an AI system

Model the AI system and trust boundaries, test model and agent abuse paths, then establish monitoring, response, and governance evidence.

  1. AI Security: Architecture, assets, trust boundaries, and AI threat modeling
  2. AI Security: Agents, tools, plugins, browsers, and MCP security
  3. AI Security: AI incident response and forensic readiness
  4. AI Security: Secure AI development lifecycle and production release gate
